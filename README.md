# Caveats and limits of microsatellite-based hybrid detection in structured populations: Example from wolf-dog hybridisation in the Northern Dinaric mountains

Iosif, R., Konec, M., Kusak, J., Marucco, F., Nowak, C., Pazhenkova, E., Promberger–Fürpass, B., 
Stronen, A. V., Šnjegota, D., Tsingarska, E., & Skrbinšek, T. *Caveats and limits of 
microsatellite-based hybrid detection in structured populations: example from wolf-dog 
hybridisation in the Northern Dinaric mountains.*

The repository contains the empirical genetic dataset, sample metadata, R scripts used 
to perform the analyses, and the resulting analysis outputs.

The repository is archived on Zenodo.

## Repository structure

The repository contains the original input data, intermediate files generated
for STRUCTURE analyses, STRUCTURE and CLUMPAK results, and outputs from the
downstream R analyses.

The main directories have the following purposes:

- `Data/` — original empirical dataset and sample metadata used as input for
  the analyses.
- `Results_of_data_exploration/` — results generated by
  `1_Data_exploration.Rmd`.

analyse a different dataset.

## Input data

### Sample_data.xlsx

This file contains two sheets (Samples_data and Allele_sequences) with the sample 
information and microsatellite genotype data used for all analyses.

The sheet Allele_sequences includes:
- marker name
- allele name, representing the allele length in base pairs. When alleles of the 
same length had different nucleotide sequences, they were distinguished using an 
underscore and a sequential number (e.g., 80, 80_1, 80_2).
- nucleotide sequence of the allele

The sheet Samples_data includes:
- sample identifiers,
- population assignments,
- sample metadata,
- microsatellite genotypes - The original dataset contains 22 microsatellite 
markers. Two markers (Cl370 and Lup01) were excluded from downstream analyses 
because they had more than 10% missing data, resulting in a final dataset of 20 markers.
Alleles for each marker are written in the same field, separated by space.


The microsatellite genotype data are formatted for import and processing using 
the R package adegenet.

## Analysis workflow

This repository contains R scripts for the preparation, analysis, and
interpretation of microsatellite genotype data for the detection of wolf–dog
hybrids and assessment of population structure. The workflow can be adapted
to other microsatellite or genetic datasets and, with appropriate modification of
population and classification settings, to other species.

The workflow includes:

- exploration of microsatellite genotype data,
- preparation of datasets for STRUCTURE analyses,
- generation of ParallelStructure joblists,
- running STRUCTURE analyses on a Linux server/HPC environment,
- downstream statistical analyses and visualization after STRUCTURE and CLUMPAK 
processing.

The analyses were performed using 20 microsatellite markers.

Analyses were performed using R version 4.3.0.

Open `26_Project_R_code.Rproj` in RStudio before running the scripts. The project
should be opened from the repository root so that relative file paths resolve
correctly.

The scripts should be executed in the following order.

---

### 1. Data exploration

Script:


1_Data_exploration.Rmd


This script imports the microsatellite dataset and performs exploratory analyses.

Analyses include:

- creation of genetic data objects,
- quality assessment of the dataset,
- principal component analysis (PCA),
- heterozygosity comparisons (Ho vs He),
- private allele analyses.

The resulting R outputs are saved in:

Results_of_data_exploration/

---

### 2. Preparation of STRUCTURE input datasets

Script:


2_Preparation_for_Structure.Rmd


This script prepares datasets for STRUCTURE analyses.

The script includes:

- filtering samples according to analysis requirements,
- generating datasets for different analyses,
- simulation of additional individuals to balance population sample sizes,
- simulation of hybrid individuals for specific analyses,
- preparation of STRUCTURE formatted genotype files,
- generation of population ID files and sample mapping files.

The resulting STRUCTURE input files are saved in:


Data_for_Structure/


Each analysis has its own folder containing the required input files for STRUCTURE.

---

### 3. Preparation of ParallelStructure joblists

Script:


3_Joblists_for_Structure.Rmd


This script generates joblist files required for running STRUCTURE analyses using 
the R package `ParallelStructure` (Besnier, F., & Glover, K. A. (2013). ParallelStructure: 
A R Package to Distribute Parallel Runs of the Population Genetics Program STRUCTURE on 
Multi-Core Computers. PLoS ONE, 8(7). https://doi.org/10.1371/journal.pone.0070651 ).

The joblists specify:

- STRUCTURE runs,
- K values,
- analysis parameters.

By default, the joblists are written to Data_for_Structure/Joblists. Before running 
STRUCTURE, the relevant joblist must be copied or moved to the corresponding 
analysis directory containing the STRUCTURE input files. The default can also be
changed so that the joblists are saved in the preferred folder.

---

### 4. Running STRUCTURE analyses

Script:

4_Run_Parallel_Structure.Rmd


This script runs STRUCTURE analyses using the `ParallelStructure` R package.

The script was designed to be run on a Linux server or HPC environment.

Before running the script, users should modify:

- the path to the STRUCTURE installation,
- the path to the dataset directory,
- the number of CPUs,
- the number of individuals (`numinds`) for the analysed dataset,
- the number of markers used and other parameters if they are running analyses
with their own data.

STRUCTURE output files are saved in:


ParallelStructure_Results/


---

### 5. STRUCTURE result processing and downstream analyses

Script:


5_Analyses_after_Structure.Rmd

Before running this script, STRUCTURE replicate results must be processed using 
CLUMPAK (e.g. I used online tool StructureSelector, which can also run CLUMPAK
and estimates optimal K). The resulting files should be placed in the Clumpak_results 
folder within the corresponding analysis directory.

This script performs analyses after STRUCTURE runs have been completed.

The workflow includes:

- processing CLUMPAK outputs,
- analysing replicate runs,
- evaluating ancestry coefficients and calculating or setting assignments 
thresholds of Q_Dog value,
- clustering samples into different groups according to the thresholds,
- visualizing thresholds (density plot) and assignment results (heatmap),
- calculating the accuracy of hybrid classifications,
- generating tables and figures.

The resulting R outputs are saved in:


R_results/


It contains outputs from the downstream R analyses and is located in the main 
directory of each analysis, alongside the simulation replicate folders.

---

## Structure of analysis results

The folder:


ParallelStructure_Results/


contains the results of STRUCTURE runs, CLUMPAK analyses, and associated outputs.

Each analysis contains separate folders for different simulation replicates generated 
using different random seeds.

Example:


ParallelStructure_Results/
└── 1c_NDinaric_empirical_Sim_dog/
  │
  ├── 1c_NDinaric_empirical_Sim_dog_1/
  ├── 1c_NDinaric_empirical_Sim_dog_2/
  ├── ...
  ├── 1c_NDinaric_empirical_Sim_dog_10/
  └── R_results/

Each replicate folder contains:


1c_NDinaric_empirical_Sim_dog_1/
  │
  ├── output files of 2_preparation_for_Structure.Rmd (1c_NDinaric_empirical_Sim_dog_1.txt, 1c_NDinaric_empirical_Sim_dog_1_POP.txt, 1c_NDinaric_empirical_Sim_dog_1_PopMap.txt)
  │
  ├── output files of 3_joblists_for_Structure.Rmd (joblist_1c_1.txt)
  │
  ├── output files of ParallelStructure
  │
  └── Clumpak_results/ 

  
  
The `Clumpak_results` folder contains processed STRUCTURE results generated by 
CLUMPAK.

The `R_results` folder contains outputs generated by: 5_Analyses_after_Structure.Rmd
including processed data tables, figures, and statistical summaries.

## Reproducing the analyses

All analyses presented in the associated manuscript have already been run,
and the corresponding input files and results are included in this repository.

The analyses can be reproduced from the provided data and code by following the
workflow below. Users can also adapt the scripts to analyse their own datasets.

To reproduce the analyses:

1. Open `26_Project_R_code.Rproj` in RStudio.
2. Install the required software and R packages.
3. Adjust file paths in the scripts where needed.
4. Run the R Markdown scripts in the order described above.
5. Run STRUCTURE analyses on Linux using code from `4_Run_Parallel_Structure.Rmd`.
6. Process the STRUCTURE results using the required CLUMPAK/StructureSelector
   workflow.
7. Run `5_Analyses_after_Structure.Rmd` for downstream analyses.

Because STRUCTURE analyses are computationally intensive, an HPC environment is 
recommended. ParallelStructure can be used to distribute replicate STRUCTURE 
runs across multiple CPU cores. The analyses can also be run directly using 
STRUCTURE v2.3.4 without ParallelStructure, although replicate runs must then be 
executed individually.
